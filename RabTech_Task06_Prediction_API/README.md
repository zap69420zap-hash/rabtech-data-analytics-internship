# RabTech Academy — Task 06: Prediction API & Containerization

## Deliverables
- `app.py` — FastAPI service with JSON `POST /predict`, class probabilities, input validation, and health endpoint.
- `Dockerfile` — reproducible container build using pinned Python dependencies.
- `requirements.txt` — pinned runtime and test dependencies.
- `tests/test_api.py` — tests for API status codes, request schema, probability output, and model.
- `.dockerignore` — excludes local development artifacts from the image build.

## What it predicts
The demo predicts the `payment_status` class from customer segment, city, category, quantity, unit price, and discount percentage. The response includes the predicted class and a probability for every class learned during training.

**Data note:** Task 03's dataset is synthetic practice data, not real RabTech or customer data. If the cleaned CSV is available, the API trains on it at startup. If it is missing or unusable, a deterministic synthetic fallback is generated so the example remains runnable. The fallback's labels come from a demo rule, not a real payment-risk policy. Model predictions are educational examples and must not be used for real payment or customer decisions.

## Architecture

```text
Client (JSON)
    |
    v
FastAPI POST /predict
    |
    v
Pydantic request validation
    |
    v
scikit-learn Pipeline
  - OneHotEncoder for categorical inputs
  - StandardScaler for numeric inputs
  - LogisticRegression classifier
    |
    v
JSON response: predicted_status + probabilities
```

## API contract

### `GET /`
Returns service information and endpoint paths.

### `GET /health`
Returns `status: ok` and whether the model used Task 03 data or the synthetic fallback.

### `POST /predict`
Example request:

```json
{
  "customer_segment": "Consumer",
  "city": "Chennai",
  "category": "Electronics",
  "quantity": 2,
  "unit_price": 799.0,
  "discount_pct": 10.0
}
```

Example response shape (class names and probabilities depend on the training data):

```json
{
  "predicted_status": "Paid",
  "probabilities": {
    "Failed": 0.18,
    "Paid": 0.61,
    "Pending": 0.21
  },
  "model_source": "task03_clean_dataset"
}
```

The response above is illustrative, not a measured prediction. Probabilities are generated by the fitted classifier and should sum to approximately 1. Input constraints produce HTTP 422 responses for missing or invalid fields.

## Run locally

Python 3.11 is recommended.

```bash
cd RabTech_Task06_Prediction_API
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
```

Open the interactive API docs at http://127.0.0.1:8000/docs.

If you run the app from this folder, it looks for the Task 03 CSV at the sibling repository path. To select a different training file, set `TRAINING_DATA_PATH` to its path.

## Run tests

From this folder after installing requirements:

```bash
pytest -q
```

## Build and run with Docker

Run these commands from the **repository root** so Docker can copy the Task 03 dataset:

```bash
docker build -f RabTech_Task06_Prediction_API/Dockerfile -t rabtech-task06-api .
docker run --rm -p 8000:8000 rabtech-task06-api
```

Then open http://localhost:8000/docs or check http://localhost:8000/health.

## Known limitations
- This is a small educational baseline, not a production payment-risk system.
- Probability calibration, external validation, model monitoring, authentication, rate limiting, and sensitive-data controls are outside this assignment scope.
- The data and predictions are synthetic and must not be represented as actual company outcomes.
